# Session change log — 2026-05-04

This document summarizes work landed in the letsgo repo for this session: runnable **auth**, **group video (mesh WebRTC)**, **meeting-go signaling + invites**, and **documentation** aligned with the architecture package.

## Summary

- **Identity**: Spring Boot (`services/auth-java/`) issues HS256 JWTs; users live in PostgreSQL with SQL migrations under `migrations/go/` (golang-migrate in Docker).
- **Meetings**: Go service `services/meeting-go/` provides JWT-authenticated **room WebSocket** mesh signaling, **HTTP user lookup** (including online flag), and a **notify WebSocket** for out-of-room invite delivery.
- **Frontend**: React (`frontend/`) home experience with group call UI, optional **TensorFlow.js** blur/custom background (updates propagated with `replaceTrack` while in a call), **browser notifications**, **incoming-call modal** with Web Audio ring tone, **toasts**, and invite/accept/decline over notify WS.
- **Runtime**: Root `docker-compose.yml` wires Postgres (host port default **5433**), migrate, auth-java, meeting-go, frontend (nginx + static build). Vite dev server proxies `/api` and `/meeting`.

## Backend (`services/meeting-go`)

| Area | Details |
|------|---------|
| Hub | In-memory **room presence**, peer join/leave relay, WebRTC message routing (`webrtc-offer`, `webrtc-answer`, `webrtc-ice`). **Notify** registry per user for invites when not necessarily in a room. **Pending invites** map (`RememberInvite`, `TakeInviteCaller`, `PeekInviteCaller`, `ForgetInvite`) to correlate accept/decline with caller. |
| HTTP | `GET /meeting/api/v1/users/lookup?email=` — returns `userId`, `email`, `displayName`, `online`. |
| WebSocket — room | `GET /meeting/ws/v1/room?token=&roomId=` — roster, `peer-joined` / `peer-left`, WebRTC relay by `targetUserId`. |
| WebSocket — notify | `GET /meeting/ws/v1/notify?token=` — client → server: `invite`, `invite-decline`, `invite-accepted`; server → client: `incoming-call`, `invite-error`, `invite-declined`, `invite-accepted`. |
| Auth | Same `LETSGO_JWT_SECRET` and user UUID as `sub` as auth-java; DB reads `users` for lookup. |

## Known limitations (intentional for prototype)

- **Mesh WebRTC** only (no SFU in this repo); small groups; TURN not wired in compose by default.
- **Presence and rooms** are process-local; horizontal scale needs Redis (or similar) before multiple meeting-go replicas.
- **DynamoDB / Elasticsearch / event bus** appear in target architecture docs but are not required for the current dev slice.
